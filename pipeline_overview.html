Architecture · Prahlada

How a chemistry question gets made

Prahlada synthesises JEE Advanced chemistry problems with an LLM, then puts every candidate through a validation loop before it is allowed into the dataset. This is the shape of that pipeline, start to finish, for someone seeing it for the first time.

01The shape at a glance

Three phases. The first two are built once and committed to the repository. The third is the one you run, over and over, to produce questions.

fig. 1 — phase overview · knowledge and thresholds feed the generation loop

Phase 0 turns teacher notes into structured chemistry: a concept book of reaction transformations, and (for organic) a reaction graph where nodes are functional-group classes and edges are valid reactions. Phase 1 runs real exam questions through the solvers to set the two acceptance thresholds and the difficulty-tag baselines. Phase 2 is the loop below.

02Inside the generation loop

One accepted question can take up to four attempts. Each attempt writes a question, checks it three ways, and either accepts it or feeds the failure back in to be repaired — never regenerated from scratch.

03What each stage does

Read fig. 2 top to bottom. Every box is one of these.

Coverage

core/coverage.py

Four inverse-frequency counters (archetype · chapter · edge · concept). Steers each new question toward the least-visited corner of the space so the set stays diverse.

Graph traversal

graph-wired path

BFS over the reaction graph produces a candidate chain where every hop is a real reaction by construction — so the model can't invent chemistry that doesn't exist.

Concept reasoner

ground-up path

When there's no graph, it filters the concept book to the chosen chapter + archetype and picks 3–4 transforms that chain together coherently.

Generator

DeepSeek-V3.2 · 0.7

Writes the question and a full worked solution from the selected steps. On a retry it refines in place — fixing only what the verifier flagged.

Verifier

DeepSeek-V3.2 · 0.0

Solves the question blind first, then compares to the candidate and runs subject-specific checks (formula balance, stereo validity, non-circularity). Returns PASS/FAIL + feedback.

Weak solver

llama3.2 · local

A non-expert baseline. If it scores above 60, the question is too easy and gets rejected.

Strong solver

DeepSeek-V3.2 · 0.0

An expert baseline. If it scores below 85, the question is treated as broken or unsolvable and gets rejected.

Meta-tags

core/meta_tags.py

On acceptance, labels the item on six difficulty axes as z-scores against the calibration corpus — length, obfuscation, fragility, exceptions, solution length, distractor plausibility.

Blackboard

core/blackboard.py

The shared working memory. Carries the full attempt history so each retry can see what failed before — this is what makes refine-in-place possible.

04The two entry paths

The whole loop is identical after generation. What differs is where the reaction chain comes from.

graph-wired

run_graph_final.py

  • Chain comes from BFS over the reaction graph
  • Every step is a validated edge — no invented chemistry
  • Organic today; inorganic once its graph is built
ground-up

run_groundup_final.py

  • No graph — builds from a filtered slice of the concept book
  • Concept reasoner picks the transforms freely
  • Works for all three subjects; the fallback where no graph exists
Where difficulty is decided. The two solvers are the difficulty gate: an item must be hard for the weak model (≤60) yet solvable for the strong one (≥85). Everything upstream exists to feed that gate a well-posed, on-topic, diverse candidate.

05What comes out

Each accepted question is appended to the subject's output file as one record — the question, its solution, the scores that cleared it, the difficulty label, and the complete attempt history.
