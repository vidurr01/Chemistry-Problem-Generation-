Pipeline overview

How one question is made, question first (the default for computed questions). The answer key always comes from the engine, run on exactly the numbers the question prints; every decision is made in code. Status: physical is wired end to end; the inorganic and organic engines are being built. Where each stage lives: docs/PIPELINE.md.

1codeDraw formulasqf_draw.py · jev-1.14
3-5 engine formulas at random, each sharing a quantity with one already drawn; Jev scores 6 sets and the best is used; a twist is drawn (inverse, ratio, difference, simultaneous, condition)
↓
2writesDesigngemini-3.1-pro-preview
One design around a hidden link: how the formulas meet through a quantity the question never names, what the student must notice, the trap there
Jev checks the design (cut-offs calibrated on real JEE designs) · rejected or impossible → new draw
↓
Refinement loop: max 3 rounds (too easy → new twist or one more formula; unclear → reworded; both back to 3)
3writesWrite with blanksgemini-3.7-flash
The question with every number as a blank [[name]] and a realistic range for it (a fixed value only for a value of the substance itself), plus a range for the answer
broken blanks → back to 3 (max 3 writes) · Jev level check (calibrated on real papers): below JEE Advanced → back to 3
↓
4writesCoder 2: the solving programgpt-6-luna · sandbox.py
solve() written from the question with its blanks, before any number exists; it calls only the drawn formulas. A probe runs it on values from the ranges
breaks, assigns to a blank, ignores a picked value, skips a needed formula → back to 4 (max 3) · cannot → back to 3
↓
5codeCoder 1: the number stepqf_numbers.py · sandbox.search_numbers
Values drawn in the ranges run through the program until a set gives an answer in the answer range, moves by at most 2 % with rounding, is changed by at least 2 typical mistakes, and uses every picked value; then they are printed in the question
no set works → back to 3 with the reason · the program breaks on some values → back to 4 once
↓
6checksChecksqf_checks.py · jev-1.14
Every formula's result matters; no intermediate stated; constants stated; not a copy of an example or an accepted question; Jev's coherence check (calibrated)
fail → back to 3
↓
7codeDuplicate checkdedup.py
Same formulas and the same printed values as an accepted question → a new question
↓
8solvesLaddergranite-4.2-8b → glm-5.3-flash → minimax-m3
Closed book, weakest first; each step only if every step below failed
↓
9codeGrading
Code only: solved = the answer is within tolerance of the key (letters and text by their shape)
↓
10codeDecision
Bottom step solves → too easy: Jev picks the likeliest of 8 cases and code applies it (new twist, one more formula) → back to 3. Bottom step fails → label (GLM: advanced or hard Mains by Jev's level check; MiniMax: advanced medium; none: hard advanced) and the code-written insight hint on each failed step
failed solver call → parked, judged first next run; after 3 failed rechecks → on hold, never dropped
↓
11writesAcceptgemini-3.8-flash
Record + readable solution (every calculation checked in code, then by the solution checker, claude-haiku-5.5) + coverage + results/

Caps: 6 draws per run · 3 writes and 3 programs per question · 200 value sets per number step · 3 refinement rounds · $0.12 per run (--max-run-spend). Router: OpenRouter first, airouter.in once it runs out of credit. The older engine-first flow (--flow engine: graph walk, the generator picks inputs, the engine computes, a chemistry gate) is described in docs/Flow.md.
