Architecture · Prahlada

How a chemistry question gets made

Prahlada synthesises JEE Advanced chemistry problems with LLMs, then puts every candidate through a validation loop before it is allowed into the dataset. This is the shape of that pipeline, start to finish, for someone seeing it for the first time.

01The shape at a glance

Three phases. The first two are built once and committed to the repository. The third is the one you run, over and over, to produce questions.

fig. 1 — phase overview · knowledge and calibration feed the generation loop

Phase 0 turns teacher notes into structured chemistry: a concept book of transformations per subject, and from it a knowledge graph per subject — functional-group classes for organic, chemical species for inorganic, physical quantities for physical. Every edge is one concept-book transformation. Phase 1 measures how hard real exam questions are for the models (the anchor) and sets the baselines for the difficulty tags. Phase 2 is the loop below.

02Inside the generation loop

One run accepts at most one question: up to three fresh ideas (lineages) and four generate-and-check iterations in total. A candidate is gated by a two-tier verifier and then by a council of three solvers that work blind (they never see the reference). On a miss the failure is fed back and the question is repaired in place.

03What each stage does

Read fig. 2 top to bottom. Every box is one of these.

Pending recheck

recheck_pending()

A question whose council check failed for an API reason is parked, not lost. The next run of that subject rechecks it before making anything new: accepted, dropped (too easy / wrong key), or parked again.

Graph traversal

core/graph_traversal.py

BFS over the subject's graph produces chains where every step is a real concept-book transformation. Chains inside the chapter come first; if there are too few, chains that start in the chapter top them up. Steps are joined on the same compound wherever the data allows.

Coverage

core/coverage.py

Inverse-frequency counters (archetype · chapter · edge · concept). Chains through rarely used edges rank higher, so the question set stays diverse.

Concept reasoner

DeepSeek-V3

Picks the most promising of the offered chains — coherent, non-circular, with a decision or trap where difficulty comes from reasoning rather than obscurity.

Generator

Gemini 2.5 Flash

Writes the question and a reference solution, carrying each step's actual product into the next step. On a retry it refines in place — fixing only what was flagged.

Verifier — two-tier

deterministic + Gemini 3 Flash

Tier 1 (no LLM): for numeric answers, hard-fails if an accepted question with the same inputs has a different answer. Tier 2: blind-solves with the candidate withheld, compares the answers, then checks arithmetic, regime of validity, uniqueness and circularity. The verdict is assembled in code.

Council

Llama · Mistral · Gemma · blind

Three Mains-level models from different families solve in parallel, blind and closed-book (only the chapter's concept-book entries). How many solve it is the difficulty signal: 2 or 3 → too easy, 0 or 1 → hard enough. All three must answer.

Grader

GPT-4o

Judges each council answer against the construction steps and the reference, with discrete true/false calls. If two or more graders say the reference answer itself is wrong, the question is refined.

Save & results

save_accepted()

The record is written first, atomically; only then coverage, the dedup store, the copy into results/ with empty human-eval slots, and the attempt log. Six difficulty meta-tags label the item.

Blackboard

core/blackboard.py

The shared working memory. Carries the full attempt history — verdicts, council results, feedback — so each retry can see what failed before.

04The two entry points

Both take their chains from the same graph traversal. What differs is how a candidate is checked.

current

run_groundup_final.py

  • OpenRouter, one model per role
  • Answer-first two-tier verifier + three-model council
  • Pending queue, results/ review, batch driver (generate_questions.py)
older

run_graph_final.py

  • SambaNova DeepSeek-V3.2 for every role + a local Ollama llama3.2 weak solver
  • Gate: verifier PASS · strong ≥ 85 · weak ≤ 60
  • Kept for comparison; prefer the current entry point

06How hard is "hard"? — the anchor

Generation makes questions; calibration measures where they sit, with the same blind protocol.

calibration/anchor_calibration.py blind-solves 54 real JEE Advanced numeric questions (2021–2025) with a strong and a weak model and grades each answer by deterministic match against the official key — no self-scoring, no model bias.

STRONG gpt-oss-120b: 50% solved (27/54) · weak llama-3.2-3b: 7% (4/54)
STRONG qwen3-235b: 37% solved (20/54) · weak llama-3.2-3b: 6% (3/54)
What the anchor is for. Even a strong reasoning model solves only about half of real Advanced numeric questions blind — that is the difficulty yardstick generated items are compared against.
